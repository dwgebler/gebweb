# Internationalisation

<!-- doctest:strict -->

`gebweb.useI18n` negotiates a request locale and optionally installs message
catalogues. Typed handlers can receive `gebweb.Locale` and
`gebweb.Translator`; templates receive a request-bound `t` function. The same
catalogues can translate typed-body validation errors.

## Wiring

Create `messages/en.yaml`:

<!-- doctest:file messages/en.yaml -->
```yaml
home:
  greeting: "Hello, {name}!"
common:
  save: Save
cart:
  items:
    one: "1 item"
    other: "{count} items"
validation:
  minLength: "Field {field} needs at least {min} characters"
```

Create `messages/de.yaml`:

<!-- doctest:file messages/de.yaml -->
```yaml
home:
  greeting: "Hallo, {name}!"
cart:
  items:
    one: "1 Artikel"
    other: "{count} Artikel"
validation:
  minLength: "Feld {field} braucht mindestens {min} Zeichen"
```

The view uses a dictionary supplied by its controller for placeholder values.
Create `templates/welcome.html`:

<!-- doctest:file templates/welcome.html -->
```html
<h1>{{ t('home.greeting', greetingArgs) }}</h1>
```

Put the application in `src/localised_app.gb`. The JSON and HTML routes share
the same catalogues, and the signup route will demonstrate validation:

<!-- doctest:file localised_app.gb -->
```gb
import gebweb;

class SignupInput {
    @Assert.minLength(8)
    string username;
}

@Controller("")
class LocalisedController extends gebweb.Controller {
    @Get("/welcome")
    func welcome(gebweb.Locale locale, gebweb.Translator translator): dict<string, any> {
        return {
            "locale": locale.tag,
            "greeting": translator.translate(locale.tag, "home.greeting", {"name": "Ada"}),
        };
    }

    @Get("/page")
    func page(gebweb.Request request): gebweb.Response {
        return this.view(request, "welcome.html", {"greetingArgs": {"name": "Ada"}});
    }

    @Post("/signup")
    func signup(SignupInput body): dict<string, any> {
        return {"username": body.username};
    }
}

export func build(dict<string, any> overrides = {}): gebweb.GebwebApp {
    let app = gebweb.app();
    gebweb.useViews(app, "templates");
    dict<string, any> options = {
        "locales": ["en", "de"],
        "default": "en",
        "messages": "messages",
    };
    for (key, value in overrides) {
        options[key] = value;
    }
    gebweb.useI18n(app, options);
    return app;
}
```

Run requests without an HTTP listener:

<!-- doctest:run -->
```gb
import gebweb;
import io;
import localised_app;

let client = gebweb.TestClient(localised_app.build());
io.println(client.get("/welcome").text());
io.println(client.get("/de/welcome").text());
io.println(client.get("/de/page").text().trim());
```

```text
{"greeting":"Hello, Ada!","locale":"en"}
{"greeting":"Hallo, Ada!","locale":"de"}
<h1>Hallo, Ada!</h1>
```

Place this setup in your normal `build(conn)` and serve through the
[standard entry point](01-getting-started.md). Configure the middleware during
startup, before requests and before gates that need the negotiated locale.

| Option | Default | Meaning |
|--------|---------|---------|
| `locales` | `["en"]` | Supported tags; use consistent canonical language/region spellings. |
| `default` | `"en"` | Fallback when no source matches; choose a supported tag. |
| `sources` | `["url", "cookie", "accept-language"]` | Sources in priority order; first match wins. |
| `cookieName` | `"gebweb_locale"` | Name of the preference cookie to read. |
| `urlPrefix` | `true` | Recognize a leading supported locale path segment. False skips URL negotiation. |
| `urlStrip` | `true` | Remove the prefix when URL negotiation selects it. |
| `defaultZone` | `""` | Zone metadata attached to the resolved locale. |
| `messages` | `""` | Catalogue directory; omitted/empty means no file-based translator. |
| `catalogs` | Omitted | In-memory `dict<string, dict<string, string>>`, keyed by locale and flat message key; takes precedence over `messages`. |

Register a translator before using translator-typed parameters. Negotiation
alone does not supply one. `catalogs: {}` does supply an empty translator,
whose missing lookups return keys.

## Locale negotiation

The default precedence is URL, then cookie, then `Accept-Language`, then the
configured default. This program demonstrates competing preferences:

<!-- doctest:run -->
```gb
import gebweb;
import io;
import localised_app;

let client = gebweb.TestClient(localised_app.build());
let preferences = {"Cookie": "gebweb_locale=en", "Accept-Language": "de"};
io.println(
    (client.request("GET", "/de/welcome", null, preferences).json() as dict<string, any>)["locale"]
);
io.println(
    (client.request("GET", "/welcome", null, preferences).json() as dict<string, any>)["locale"]
);
io.println(
    (client.request("GET", "/welcome", null, {"Accept-Language": "de;q=0.9,en;q=0.5"}).json() as dict<string, any>)["locale"]
);
```

```text
de
en
de
```

URL prefixes match an entire segment: `/de` and `/de/...` match `de`, while
`/debug` does not. A prefix-only request becomes `/` when stripped. Unsupported
prefixes remain part of the route path; they do not automatically redirect or
return a locale-specific error.

Cookie values and URL segments match configured tags exactly. Header matching
uses quality ranking and exact/language-prefix matches against the supported
list; ties retain the first matching preference. It is a small negotiator,
not a full language-range implementation: do not rely on wildcard expansion or
case-insensitive canonicalization of arbitrary header tags.

### Disabling prefix recognition or stripping

`urlPrefix: false` leaves the original path intact and continues with the
other sources. `urlStrip: false` still selects the URL locale but keeps the
prefix, so routes must include it. Removing `"url"` from `sources` also stops
URL recognition. Reordering sources can prevent a prefix being stripped: when
a cookie wins first, the URL source is never evaluated.

Negotiation reads a preference cookie; it does not create or persist one.
Implement a language-choice endpoint/cookie policy if your app needs it.

## Locale injection

`gebweb.Locale` is an alias of `gebweb.i18n.Locale`. The resolved value lives
on the request and is injected into typed handler parameters, not into a
shared controller constructor:

| Field | Meaning |
|-------|---------|
| `tag` | Normalized language and optional region, such as `en-GB`. |
| `language` | Lowercase primary language, such as `en`. |
| `region` | Uppercase region or an empty string. |
| `zone` | The configured `defaultZone`, or empty. |

`parseLocale` normalizes underscore separators and language/region casing.
It is not a complete BCP-47 validator and does not retain script/extension
subtags. Use explicit supported tags rather than treating parsing as validation
of untrusted locale input:

<!-- doctest:run -->
```gb
import gebweb;
import io;

let locale = gebweb.parseLocale("en_gb") as gebweb.Locale;
io.println(locale.tag);
io.println(locale.language);
io.println(locale.region);
io.println(gebweb.parseLocale("") == null);
```

```text
en-GB
en
GB
true
```

The zone field is metadata. The formatting helpers below do not convert
instants between time zones or validate zone names.

## Translation catalogs

`messages` reads immediate `.yaml` and `.yml` files, using the filename stem as
the locale key. Nested YAML keys flatten with dots, so `home.greeting` above
is one lookup key. Keep file tags consistent with the configured tags.
A missing directory loads an empty catalogue map; malformed YAML can fail
setup. Catalogues load once, with no file watcher/reload behavior.

Lookup tries the exact requested locale and the configured default, then
returns the key. It does not add a parent-language step (`de-AT` to `de`). An
empty exact-locale entry suppresses the default value for that same lookup:
a plain-key translation then returns the key, while plural lookup can try its
other/plain candidates. Omit unavailable entries rather than storing empty
strings. Placeholder substitution replaces supplied
`{name}` strings; missing arguments remain visible in the result:

<!-- doctest:run -->
```gb
import gebweb;
import io;
import localised_app;

let app = localised_app.build();
io.println(gebweb.t(app, "de", "common.save"));
io.println(gebweb.t(app, "de-AT", "home.greeting", {"name": "Ada"}));
io.println(gebweb.t(app, "de", "missing.key"));
io.println(gebweb.t(app, "de", "home.greeting"));
```

```text
Save
Hello, Ada!
missing.key
Hallo, {name}!
```

`gebweb.t` accepts either a locale tag string or a `Locale`. Without i18n or a
translator it returns the key. View `t(key, args)` uses the current request
locale; normal template escaping still applies to its result. Do not mark
translations containing untrusted arguments as raw HTML.

Catalogue paths are filesystem paths relative to the working directory unless
absolute. Provision those files with a deployed binary, or supply an explicit
resource path/in-memory `catalogs`; the loader does not automatically rebase
`messages` under `sys.bundleDir()`. Keep catalogue data read-only while serving.

## Pluralisation

A nested catalogue such as `cart.items.one` / `cart.items.other` supplies
variants. Pass an integer `count` to select a category and interpolate it:

<!-- doctest:run -->
```gb
import gebweb;
import gebweb.i18n as i18n;
import io;
import localised_app;

let app = localised_app.build();
io.println(gebweb.t(app, "en", "cart.items", {"count": 1}));
io.println(gebweb.t(app, "en", "cart.items", {"count": 5}));
io.println(gebweb.t(app, "de", "cart.items", {"count": 5}));
io.println(i18n.pluralForm("ru", 3));
io.println(i18n.pluralForm("ar", 2));
```

```text
1 item
5 items
5 Artikel
few
two
```

These are hand-coded integer rules, not a complete CLDR/ICU message engine:

| Languages | Categories used |
|-----------|-----------------|
| `zh`, `ja`, `ko` | `other` |
| `fr`, `pt` | `one` for 0/1, otherwise `other` |
| `ru`, `uk`, `pl` | `one`, `few`, `many` |
| `ar` | `zero`, `one`, `two`, `few`, `many`, `other` |
| Other languages | `one` for 1, otherwise `other` |

Negative counts use their absolute value for category selection. Lookup tries
`key.<category>`, then `key.other`, then the plain key. Each lookup can fall
back to the default catalogue, so keep plural variants complete across locales.
`pluralForm` takes a language code, not a region tag; use `locale.language`
when calling it directly.

## Validation messages

Typed handler-body validation uses `validation.<code>` from the request's
translator. It supplies `{field}` and the failure's rule parameters, such as
`{min}` for `minLength`. With the example catalogue and signup route:

<!-- doctest:run -->
```gb
import gebweb;
import io;
import localised_app;

let client = gebweb.TestClient(localised_app.build());
let response = client.post("/de/signup", {"username": "ab"});
io.println(response.status);
io.println(response.text().contains("Feld username braucht mindestens 8 Zeichen"));
```

```text
422
true
```

Codes follow the registered assertion names, including custom assertions;
they are not limited to a small fixed list. See [Validation](05-validation.md)
for the rules and parameter names. If no catalogue provides the code, the raw
validation message is retained. Boot-time configuration validation has no
request locale and is not translated by this request middleware.

## Number and date formatting

Import `gebweb.i18n` explicitly. Bare `import i18n` selects the language's
separate stdlib catalogue module.

<!-- doctest:run -->
```gb
import gebweb.i18n as i18n;
import io;

io.println(i18n.formatNumber(1234567, "de"));
io.println(i18n.formatNumber("1234.56", "fr"));
io.println(i18n.formatNumber("1234.50", "en"));
let parts = {"year": 2026, "month": 6, "day": 3};
io.println(i18n.formatDate(parts, "en-US"));
io.println(i18n.formatDate(parts, "en-GB"));
io.println(i18n.formatDate(parts, "de", "long"));
```

```text
1.234.567
1 234,56
1,234.50
06/03/2026
03/06/2026
3 Juni 2026
```

Number formatting groups a plain numeric representation and changes separators;
it does not round, pad decimal places, format currencies or apply an IANA zone.
Use a plain decimal string when preserving explicit trailing zeroes matters;
choose monetary rounding separately. `numberSeparators(locale)` exposes the
`thousands`/`decimal` pair. This is a small language-based convention table,
not comprehensive region-sensitive formatting.

Dates take valid integer `year`, `month`, `day` parts. `style: "long"` uses
month names; other styles use numeric formatting. Long month tables cover
English, German, French, Spanish, Italian, Portuguese, Russian and Polish;
other languages generally use English month names, with dedicated numeric
long formats for Japanese/Chinese. These helpers do not validate calendar
parts or perform time-zone conversion.

## Caching localised responses

Framework `@Cache` keys include the negotiated locale tag, so URL, cookie and
header choices do not share a translated response. Declared header variation
and authenticated user scope still apply. Invalidating a translation tag drops
all its cached locale variants; deploy/invalidate cached responses when message
catalogues change.

This concerns the framework response cache. Shared HTTP caches/CDNs also need
a policy that distinguishes language preferences. i18n does not automatically
emit `Vary`, `Content-Language` or cache-control headers. Configure them for your
URL/cookie/header strategy, preserving any existing Vary dimensions. For
manual deletion with `gebweb.cache.cacheKey`, use the routed request including
its `_locale` metadata. See [Caching](10-caching.md).

## Reference

| Helper | Purpose |
|--------|---------|
| `gebweb.useI18n(app, opts = {})` | Mount negotiation and optionally load catalogues; returns the app. |
| `gebweb.Locale` / `gebweb.Translator` | Aliases for request-injected locale/translator types. |
| `gebweb.parseLocale(tag)` | Parse the supported language/region form; null for an empty tag. |
| `gebweb.t(app, locale, key, args = {})` | Translate outside a handler/view; key fallback when unavailable. |
| `gebweb.i18n.loadCatalogs(dir)` | Load and flatten YAML files. |
| `gebweb.i18n.Translator(catalogs, defaultTag = "en")` | Construct a translator directly from flat catalogues. |
| `gebweb.i18n.pluralForm(language, count)` | Integer plural category. |
| `gebweb.i18n.numberSeparators(locale)` | Thousands and decimal separators. |
| `gebweb.i18n.formatNumber(value, locale)` | Group a plain numeric representation. |
| `gebweb.i18n.formatDate(parts, locale, style = "short")` | Format valid date parts. |

See [Views](04a-views.md), [Validation](05-validation.md),
[Caching](10-caching.md) and [Deployment](37-deployment.md).
